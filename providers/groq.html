Groq: the LPU, now Nvidia's Groq 3 LPX

A chip built around on-chip SRAM instead of HBM, and a compiler that plans every step in advance. Groq's own racks have served GroqCloud since the first LPU. Its newest silicon, the Groq 3 LPU, now ships as a rack from Nvidia.

LPU v1 / GroqRack→ Groq 3 LPU (Nvidia LPX)

Is Groq "acquired by Nvidia"? Widely described that way, but not legally. On 24 December 2025 Nvidia signed a non-exclusive licence to Groq's inference technology. Founder Jonathan Ross, president Sunny Madra and other staff joined Nvidia. Nvidia's annual report says no customer contracts, existing products or equity were bought, and total consideration is $13.0B paid at closing plus $4B due within a year (about $17B; press reports say about $20B PRESS).

Groq stays independent under CEO Simon Edwards and still runs GroqCloud. The newest LPU silicon, the Groq 3 LPU, now ships under Nvidia's name (LP30, in the Groq 3 LPX rack). Bloomberg reported in September 2026 that the US Justice Department is examining whether the structure avoided merger review PRESS; no findings have been reported.

Power & liquid cooling

Nvidia's MGX ETL rack, fully liquid-cooled

Why it's special: Groq's own racks were air-cooled. The LPX moves to Nvidia's standard rack, so it can sit beside a Vera Rubin rack and share the same cooling and power plant. Nvidia's technical blog calls the trays "cableless".

Partner rack

Vera Rubin NVL72 next door

One or more LPX racks pair with each NVL72 · full page on Nvidia

Why it's special: the LPX is not meant to run alone. GPUs read the prompt (prefill) and handle the attention step during decode; LPUs handle the feed-forward step. Nvidia's Dynamo software splits each token between the two racks. A Rubin GPU has 288 GB of HBM4 at about 22 TB/s, so it holds the long context while the LPUs supply the speed.

Connects to

Concept

Liquid cooling & the MGX rack

MGX is Nvidia's modular rack standard, so different compute and network trays fit the same frame. Liquid cooling pumps coolant through plates on each chip, because air can't remove this much heat from so many chips.

Analogy: a standard shelving system. Any tray fits any slot, and the plumbing is already there.
Concept

What is a compute tray?

A tray is a flat drawer that slides into the rack, holding several accelerators, a host CPU and network chips on one board.

Analogy: books on a shelf. Pull one out without moving the rest.
Concept

What is a chip-to-chip network?

Each LPU holds only a slice of the model, so chips must pass results to each other constantly. In a normal network, a packet can wait in a queue. On Groq's, the compiler decides which link carries what in which clock cycle, so no queue forms.

Groq's design is a "direct" network: chips connect to chips, with no central switch in between.

Analogy: a train timetable where every train's slot is fixed in advance, versus a motorway where you hope for no jams.
Concept

What is an LPU?

An LPU (language processing unit) is Groq's name for its chip, built for running language models, not training them. Groq's first chip was called a TSP (tensor streaming processor): data streams past fixed blocks of compute units, instead of waiting in caches.

It holds the whole model in on-chip SRAM, and many chips share a model (see "why many chips").

Analogy: an assembly line, not a workshop. Parts move past stations that each do one job.
Concept

SRAM vs HBM

SRAM sits on the chip itself and is very fast, but each bit takes a lot of silicon, so there isn't much of it. HBM is stacked DRAM beside the chip: much bigger, but slower to reach.

GPUs use HBM (a Rubin GPU has 288 GB at ~22 TB/s). The LPU uses only SRAM: far faster, far smaller.

Analogy: the papers on your desk versus the filing cabinet down the hall.
Concept

Prefill vs decode

Prefill reads your whole prompt at once: lots of maths, so GPUs are good at it. Decode writes the answer one token at a time, and each token must re-read the model's weights from memory. Decode is limited by memory speed, not maths.

That is the LPU's job: its fast SRAM speeds up decode.

Analogy: reading a book fast (prefill) versus writing a reply by hand, one word at a time (decode).
Concept

What is a host CPU?

Accelerators can't run an operating system. A host CPU boots the machine, loads data and handles everything that isn't matrix maths.

Analogy: the head chef who reads the orders and hands tasks to the line cooks.
Concept

What is a DPU?

A data processing unit is a network card with its own CPU cores. It takes over networking, storage access and security so the main chips don't have to. A plain NIC (like ConnectX-9) just moves data fast.

Analogy: a building's mailroom and security desk.
Concept

What is GroqCloud?

GroqCloud is Groq's rented inference service: you send text to an API, and models run on Groq's own LPU racks in its data centres. You never touch the hardware.

Analogy: ordering from a restaurant instead of buying the kitchen.

Compute

Matrix units (MXM)

One on each edge · 320 × 320 array · 4 planes in total

Why it's special: the matrix units sit at the outer edges and multiply grids of numbers as streams of data flow through. Each plane stores 102,400 weights on-chip. Because the compiler knows exactly when each number will arrive, there is no cache or scheduler to wait on.

Key numbers (whole chip)

750 TOPSINT8 peak (900 MHz)
188 TFLOPSFP16 peak
409,600weights held across 4 planes (derived: 4 × 102,400)

What it does

  • Does the heavy matrix maths of each model layer.
  • Groq 3: Nvidia quotes 1.2 PFLOPS FP8 per LPU. These are different chips and number formats, so they aren't directly comparable.

Data movement

Switch units (SXM)

One in each half · shift, permute, transpose

Why it's special: maths often needs data rearranged first, for example flipping a grid on its side. The SXM does that reshuffling in the stream, so no extra trip through memory is needed.

What it does

  • Shifts data up or down the lanes.
  • Permutes and transposes tensors as they pass.

Memory

On-chip SRAM (MEM)

88 slices · 44 in each half · 20 tiles per slice

Why it's special: this is the model's main storage, not a cache. The compiler places every tensor at a known address. There is no HBM on the chip, so the weights sit within a few millimetres of the maths.

Key numbers

230 MBSRAM per chip (220 MiB in the paper)
80 TB/son-die bandwidth, up to
0HBM stacks

What it does

  • Holds weights and working data for the layers this chip owns.
  • Capacity is the catch: a 70B-parameter model at 8-bit is about 70 GB, so it needs at least 300 chips (derived: 70 GB ÷ 230 MB).
  • Groq 3 keeps the same idea at about 500 MB and 150 TB/s per chip.

Compute

Vector unit (VXM)

Centre of the chip · 16 processing elements per lane

Why it's special: everything in a model that isn't a big matrix multiply (adding, activation functions, scaling) happens here. It sits in the middle so data from either half reaches it quickly.

Key numbers

5,12032-bit operations per cycle

  • Applies activation functions and element-wise maths.

Connects to

Control

Instruction control units (ICU)

144 instruction queues on the chip

Why it matters: a GPU decides at run time what to do next. The LPU can't: its instructions were fixed by the compiler. The ICU just plays them back at the exact cycle, and there are no branch predictors, caches or dynamic schedulers to add surprises.

What it does

  • Fetches and sends instructions to the slices, which then act on data as it streams past.
  • Unlike the slices, the ICU is drawn laid out sideways.

Connects to

Redundancy

Spare superlane

21 superlanes built, 20 used

Why it's special: a chip this regular can hide one spare row. If manufacturing leaves one superlane faulty, the chip is still usable, which improves yield. The compiler never sees the spare.

What it does

  • Lets a die with a single superlane fault count as "all good".
  • Each superlane is 16 lanes wide; 20 give the chip's 320-element vector.

Why it's special: there is no HBM, so the chip's only way out is to its neighbours. Groq's compiler schedules traffic across these links just like on-chip data, so a 300-chip system behaves like one big deterministic machine.

Concept

Deterministic execution

Deterministic means the same input always takes exactly the same number of clock cycles. A GPU uses caches and run-time scheduling that make timing vary a little. The LPU has no caches, branch predictors or dynamic schedulers, so timing is known before the program starts.

That makes speed predictable, and lets the compiler plan data movement and even power.

Analogy: a metro on a fixed timetable versus a taxi whose route depends on traffic.
Concept

Compiler scheduling

A compiler turns a model into chip instructions. Usually the chip then adjusts on the fly. On the LPU the compiler decides everything in advance: which data sits where, which slice acts when, and which link sends what.

Analogy: a choreographer who writes every dancer's position for every beat, so no one needs to improvise.
Concept

Why many chips for one model?

The model's weights must fit in on-chip SRAM, and each LPU holds only 230 MB (v1) or about 500 MB (Groq 3). A 70B-parameter model at 8-bit is about 70 GB, so it is split layer by layer across hundreds of chips (derived: at least ~300 v1 chips).

Nvidia says a trillion-parameter model needs 4 to 8 LPX racks PRESS.

Analogy: a library too big for one room, so each room holds a few shelves and a corridor joins them all.
Concept

What is a matrix unit?

AI models are mostly matrix multiplications: grids of weights times grids of inputs. A matrix unit is a block of hardware that does a whole grid at once. Groq's holds 320 × 320 weights.

Analogy: a loom that weaves a whole row of thread at once instead of one thread at a time.
Concept

What is a switch / permute unit?

Maths needs data in a particular order. The SXM shifts, permutes (reorders) and transposes (flips rows and columns) data as it passes by.

Analogy: a card dealer reshuffling the deck between hands.
Concept

What is a vector unit?

Between matrix multiplications, a model applies simpler steps to each number: adding, scaling, squashing values with an activation function. A vector unit does one such step on a whole row at once.

Analogy: a rubber stamp the width of the page, stamping every item on the line together.
Concept

What is an instruction control unit?

A chip needs something to tell its blocks what to do and when. Most chips decide this as they go. The LPU's ICUs hold a script written by the compiler and read it out on the right cycle.

Analogy: a stage manager calling cues from a script, not making them up.
Concept

What is a spare row (yield redundancy)?

Chips are cut from silicon wafers, and tiny flaws ruin some. Yield is the share that works. Building one extra copy of a repeated unit lets a chip with a single flaw still pass.

Analogy: a spare tyre. You only notice it when you need it.

Why the compiler is the product. The LPU has no caches or run-time scheduler, so the chip alone can't run anything well: the compiler does the work a GPU's hardware does on the fly.
